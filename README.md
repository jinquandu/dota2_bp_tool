# Dota2 BP 分析辅助工具

一个交互式的 Dota2 BP(Ban/Pick)分析工具,帮助评估双方阵容的协同、克制、单点强度,并提供战队英雄熟练度画像。

> **在线访问**:[jinquandu.github.io/dota2_bp_tool/bp_analysis.html](https://jinquandu.github.io/dota2_bp_tool/bp_analysis.html)(推荐,直接打开可交互页面)
>
> 也支持离线使用:下载本仓库后双击 `bp_analysis.html` 即可在浏览器打开,无需服务器,数据全部内嵌在同目录 `.js` 文件里。

---

## 这个工具解决什么问题

BP 分析的核心问题是:**给定双方 10 个英雄的阵容,谁占优?优势来自哪里?**

传统做法靠直觉("这个英雄克那个英雄"),但直觉不可靠——一个英雄的整体胜率(单点强度)、和特定队友的契合度(协同)、对特定对手的压制力(克制)是三个**独立**的维度。本工具把这三个维度量化,并允许实时调整阵容、权重、微调关系值,看到综合净优势如何变化。

此外,同样一个英雄在不同战队手里表现差异巨大。工具额外提供**战队 × 英雄熟练度画像**(基于 TI 正赛数据),让 BP 分析不止看英雄本身,还看"这个战队的这个英雄练得怎么样"。

## 功能一览

| 功能 | 说明 |
|------|------|
| **阵容加载** | 从下拉框选一场 TI 对战(共 324 场),或输入 match_id,或随机一场 |
| **关系矩阵** | 10×10 矩阵:对角线=单点强度(胜率偏离 50%),上三角=同队协同,下三角=跨队克制 |
| **综合净优势** | `net_edge = a·协同 + b·克制 + c·强度`,三个权重可滑动调整 |
| **阵容编辑** | 点击槽位可换人(自动推荐使 net_edge 最优的候选)、删除、撤销/重做 |
| **关系微调** | 单元格右上角 +/- 按钮可手动覆盖任意关系值(±0.01 步进),导出 JSON 供离线合并 |
| **战队熟练度画像** | 双方各 5 英雄的多指标对照(场次/胜率/熟练度/经济分位/致死分位)+ 战队英雄池 Top6 |

## 评分方法实现

### 三个独立维度

工具把阵容优劣拆成三个互不干扰的分量,最终汇总成净优势 `net_edge`:

#### 1. 单点强度(Power)
每个英雄在当前版本的整体胜率偏离 50% 的程度。
- 计算:基于该英雄所有出场比赛的胜率,减去 0.5
- 例:某英雄整体胜率 60%,则 `power = +0.10`
- 阵容级:`power_edge = Σ(我方 power) − Σ(敌方 power)`

#### 2. 协同(Synergy)
同队两个英雄一起出场时,胜率相对各自基线的**增量**。
- 计算:`delta = 实际同队胜率 − (英雄A基线 × 英雄B基线的期望)`
- 例:英雄 A 单独胜率 50%、B 单独 50%,但一起出场胜率 65%,则协同 `delta ≈ +0.15`
- 阵容级:`syn_edge = Σ(我方 10 对协同) − Σ(敌方 10 对协同)`

#### 3. 克制(Counter)
跨队两个英雄对位时,一方相对其基线的胜率增量。
- 计算:与协同类似,但分母是跨队对位
- 例:英雄 A 对位英雄 B 时胜率 65%(基线 50%),则 `A 克 B 的 delta = +0.15`
- 阵容级:`cnt_edge = Σ(我方克敌方) − Σ(敌方克我方)`

### 小样本抑制(Shrinkage)

冷门英雄/组合出场次数少,统计噪声大。工具用**经验贝叶斯收缩**抑制:

```
lookup 值 = delta × reliability
reliability = min(1, games / 30)   # 出场满 30 场才视为满分可靠
```

例:某对协同实际 delta=+0.20,但只出场 15 场,则 `reliability = 0.5`,最终贡献 `+0.10`。

### 极值硬截断(Clip)

避免少数极端值主导评分。所有关系值(synergy / counter / power)统一截断到 **±0.20**:

- 截断在数据生成层(`compute_edges.py`)完成,前端、CSV、覆盖表口径一致
- 影响的是 P99 之外的尾部(约 48 个值被截),主体分布(P1–P99)不受影响
- 用户手动覆盖的值优先级最高,不被截断

### 综合净优势

```
net_edge = a · syn_edge + b · cnt_edge + c · power_edge   (默认 a=b=c=1)
```

| net_edge 绝对值 | 解读 |
|----------------|------|
| > 0.8 | 压倒性优势 |
| 0.5–0.8 | 明显优势 |
| 0.3–0.5 | 倾向优势 |
| 0.1–0.3 | 微弱倾向 |
| < 0.1 | 势均力敌 |

> **注意**:net_edge 只反映英雄关系层面的阵容优劣,不含选手状态、战术执行等因素。它适合作为 BP 决策的**参考维度之一**,不是预言胜负。

## 战队熟练度画像

这是一个**独立于评分体系**的展示功能——熟练度不进 `net_edge`,只帮助理解"这个战队的这个英雄练得如何"。

### 数据来源

TI2026 正赛 16 支战队的英雄级表现(435 个战队×英雄组合,每组合 ≥5 场)。

### 展示指标(每个 0–100,越高越好)

| 指标 | 含义 |
|------|------|
| **场次** | 该战队使用该英雄的出场次数 |
| **全量胜率** | 该英雄在所有战队的胜率(参考基线) |
| **近5胜率** | 该战队该英雄的胜率 |
| **经济分位** | 该战队使用该英雄时,经济(GPM)在全量分布中的百分位 |
| **致死分位** | 该战队使用该英雄时,致死伤害均摊值在全量分布中的百分位 |
| **熟练度** | 综合分,公式:`0.6 × 近5胜率 + 0.2 × 经济分位 + 0.2 × 致死分位`,归一到 [50, 100] |

### 战队别名处理

TI 有 4 支战队在数据里用了不同的队名(预选一个名、正赛改名),工具自动归一:

| TI 正赛名 | 数据里的别名 |
|-----------|-------------|
| BetBoom Team | BB |
| Iron Wing | Tundra Esports |
| TEAM VISION | PARIVISION |
| HULIGANI | L1GA TEAM |
| LGD Gaming | HEROIC, ex-HEROIC |

## 数据文件说明

`bp_analysis.html` 通过同目录的 4 个数据文件加载全部数据(无需后端):

| 文件 | 大小 | 内容 |
|------|------|------|
| `bp_data.js` | ~96 KB | 127 英雄表 + 协同/克制/baseline 关系表 + meta |
| `bp_rosters.js` | ~492 KB | 2130 场比赛的阵容索引(match_id → 双方 5 英雄) |
| `bp_teams.js` | ~71 KB | 16 支 TI 战队 × 84 英雄的熟练度画像 |
| `bp_analysis.html` | ~50 KB | 页面本体(HTML + CSS + JS 全在一个文件) |

数据范围:**2026-04-01 至 2026-08-09**,基于 ≥Tier1 级别职业赛事(2255 场)。

---

## 本地使用

无需安装任何环境,只需把 4 个文件(`bp_analysis.html` + 3 个 `.js`)放在同一目录,双击 HTML 即可在浏览器打开。

也支持从下拉框选择 TI 对战(已预过滤为"双方都是 TI 16 队"的 324 场),或直接输入 match_id 加载任意一场。

---

## 数据更新

数据由 `compute_edges.py` 从 [OpenDota API](https://docs.opendota.com/) 抓取的 Tier1 职业赛数据计算生成。熟练度数据来自独立的 TI 正赛特征工程流程。如需更新数据窗口或重新计算关系表,需在原始项目环境运行生成脚本(本仓库不包含原始数据和生成代码)。

---

## 局限性

- **样本量**:部分冷门英雄/组合出场不足,关系值的置信度较低(已用 shrinkage 缓解,但仍需谨慎解读)
- **版本依赖**:数据基于特定版本窗口(2026-04 至 2026-08),版本更新后英雄强度会变化
- **TI 画像覆盖**:熟练度画像只覆盖 16 支 TI 战队,非 TI 战队的比赛该面板显示"无数据"
- **评分不含人为因素**:net_edge 不反映选手状态、教练战术、临场发挥
